# P6：I2_V_4 分块提升转置实验

2026-11-17。实验仅比较同系统的正确性修复版 OFF 与打开单项 B=16 遍历开关的 ON，不使用作者错误输出的版本作基线。**默认保持 OFF。内核单线程有可重复收益，多线程存在噪声/退化观察；真实模型确认也已完成：收益依赖模型/线程，存在回退，不默认启用。**

## 改了什么

`ggml-vlut-widen.h` 增加按 16 输出行分块的提升转置 helper，只有 `ggml_gemm_i2v4_i8v_lut` 的四个提升位置调用它。旧循环先 token 后全部行，源读取步长 64 字节；新循环先处理 16 行的全部有效 token，源块为 1024 字节。目标仍是 token-major INT32 累加器。

保持原 K=128 安全段、权重字节、激活量化、INT16/INT32 数值、输出布局和独立 memset。I1 不走该 helper。这个改动没有训练要求、GPU 要求或新依赖；是已有局部性技术在此实现中的工程应用，不是已确认的新研究贡献。最近邻边界见 [文献审查](LITERATURE_REVIEW.md)。

## 正确性与构建

正式内核运行 `p6-20261117-232703-401`，源码 `4087199d`，GCC 13.3 / Release/native / T=32 / W=16 / AVX512 OFF。OFF、ON、ASan-ON、profile-OFF、profile-ON 五构建均通过：

- I2 P1：164 项、5 个非法输入和大工作区。
- I1 P4：225 项、K=4 独立图和 5 个非法输入。
- 实际 helper：135 项独立坐标参考、符号极值、尾行/token、非零初值和 canary；源缓冲区不变。

首次 `p6-20261117-232347-416` 仅做 RelWithDebInfo 预检，审查发现与既有性能构建等级不同，在正式计时前停止并改为 Release。此停止记录保留，不混入结果。正确性测试包含四个调用位置的完整/尾 token、完整/余 K 组合。

## 无插桩图级结果

8 个预先固定配置，每版本每批 5 个样本，校准目标为 1 秒；M=17 小边界受 4096 次迭代上限影响，实际约 0.19 秒，不将该组用于宣称小收益。两批次序 OFF→ON、ON→OFF，第二批反向遍历配置，共 160 样本。两批在同一会话，不是跨日复验。

| M / K / N / 线程 | 第一批 OFF/ON 延迟比 | 第二批延迟比 | 两批综合比 | 最大 CV |
|---|---:|---:|---:|---:|
| 3200 / 3200 / 1 / 4 | 1.020 | 1.057 | 1.039 | 4.9% |
| 3200 / 3200 / 32 / 1 | 1.095 | 1.087 | 1.091 | 0.9% |
| 3200 / 3200 / 128 / 1 | 1.086 | 1.055 | 1.070 | 3.1% |
| 3200 / 3200 / 128 / 4 | 1.016 | 1.104 | 1.059 | 5.7% |
| 8640 / 3200 / 128 / 1 | 1.132 | 1.099 | 1.115 | 1.4% |
| 3200 / 8640 / 128 / 4 | 1.018 | 1.012 | 1.015 | 2.1% |
| 8192 / 2048 / 33 / 4 | 0.912 | 1.021 | 0.965 | 12.0% |
| 17 / 144 / 33 / 4 | 1.013 | 1.031 | 1.022 | 4.2% |

比值大于 1 表示 ON 更快；两批综合取各批中位延迟比的几何平均，不能把 1.115x 写成“耗时降低 11.5%”（对应约 10.3%）。三个单线程配置的描述性 bootstrap 95% 区间分别为 [1.085,1.102]、[1.034,1.086]、[1.098,1.128]。其余五组区间均包含 1，不宣称确定收益。

N=33/Falcon 大输出行的第一批实际耗时上升约 9.6%，第二批反向，最大 CV 12%。这是必须保留的不稳定/退化观察，不能只选第二批。未据这两批确定原因，不能无硬件计数就归因为 cache miss。

## 分段诊断

另跑 4 对配置、每版本 5 样本，共 40 个插桩样本。数字为工作线程耗时之和，不是无插桩总墙钟：

| 配置 | 提升转置 OFF→ON，µs | 清零 OFF→ON，µs |
|---|---:|---:|
| 3200×3200，N1，4t | 68.45→68.32 | 34.28→35.18 |
| 3200×3200，N128，1t | 4143.23→3097.67 | 275.15→277.94 |
| 3200×3200，N128，4t | 3688.15→3156.31 | 128.32→200.93 |
| 8640×3200，N128，1t | 11743.53→8609.14 | 804.46→977.71 |

单线程目标配置的提升转置耗时约下降 25%–27%，图级综合加速约 7%–12%，说明局部改善会被其他阶段稀释。清零代码没有改，但计时仍有上升：遍历顺序会改变后续工作集状态，插桩和系统噪声也可能影响；目前只能报告现象，不能作精确因果断言。N1 的提升阶段基本无变化，符合有效 token 少、源数据复用少的预期。

## 真实模型 OFF/ON 结果与决定

运行 `p6-models-20261117-233509-404`，源码 `be1486ea`。两个固定 I2 GGUF、P128、B1；Prefill 测 1/4 线程，Decode 测 4 线程/G16。每配置每版本每批五次，两批反向顺序，共 120 样本。另做两模型 OFF/ON smoke；所有对应生成 token 相同、logits 有限、计时区 major faults=0、未观察到 swap 活动。

| Model / mode / threads | Batch 1 OFF/ON tokens/s | Speedup | Batch 2 OFF/ON tokens/s | Speedup | Max CV |
|---|---:|---:|---:|---:|---:|
| falcon3-1b-i2v4 / prefill / 1 | 73.33/74.22 | 1.012x | 73.61/73.56 | 0.999x | 5.9% |
| falcon3-1b-i2v4 / prefill / 4 | 227.77/225.44 | 0.990x | 230.46/228.47 | 0.991x | 1.8% |
| falcon3-1b-i2v4 / decode / 4 | 9.42/8.96 | 0.951x | 9.12/8.95 | 0.981x | 3.1% |
| bitnet-3b-i2v4 / prefill / 1 | 22.07/27.36 | 1.240x | 25.95/27.83 | 1.072x | 2.0% |
| bitnet-3b-i2v4 / prefill / 4 | 82.86/85.85 | 1.036x | 86.48/86.73 | 1.003x | 2.8% |
| bitnet-3b-i2v4 / decode / 4 | 3.85/4.02 | 1.044x | 4.16/4.10 | 0.987x | 3.6% |

判定：

- **BitNet 单线程 Prefill 有正向证据，但幅度不稳定。** 两批分别 1.240x 与 1.072x。OFF 中位耗时从 5799.25 ms 变为 4931.78 ms，ON 从 4677.90 ms 变为 4599.84 ms；批内低 CV 不排除批间环境变化。因此不把首批 24% 吞吐增幅当稳定收益，也不能简单平均后宣传。
- **Falcon3 单线程 Prefill 无明确收益。** 两批接近 1，最大 CV 5.9%。Falcon3 四线程 Prefill 约 1% 的下降也接近噪声。
- **Falcon3 四线程 Decode 两批均退化。** 吞吐分别下降约 4.9%/1.9%（耗时分别增加约 5.1%/2.0%），不省略这两个结果。
- **BitNet 四线程未得到稳定收益。** Prefill 从 3.6% 缩至 0.3%，Decode 两批方向相反。不宣称四线程有效。

最终保留 `VLUT_I2V4_BLOCKED_WIDEN=OFF` 为默认。实验满足“局部实现、正确性、总耗时与退化检查”，但不满足“默认全场景加速”的条件；没有把分块包装成已确认的研究创新。暂不增加更多块长、融合清零或改动数值精度。下一轮如继续，应先在固定 CPU 资源下复核 BitNet 单线程 Prefill，再考虑按真实行数/token 数选择性启用；该选择策略尚未实现或验证。

本次实际范围为八组图级配置及六组模型负载，未做原候选的全形状/全 N 优化网格。直接增加模型确认，是为了尽早识别局部收益无法传播和实际退化，之后按结果停止普遍启用该候选。

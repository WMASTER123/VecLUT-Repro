## 1. 成功标准

本阶段完成不是“生成一段文字”或“跑完一个脚本”，而是同时满足：

1. 固定环境与版本能重新构建。
2. 能解释论文核心机制，并定位到实际执行代码。
3. I2 与 I1 的目标路径有必要的正确性证据。
4. 至少在一个真实模型上完成内核、Prefill 和小规模并行生成测试。
5. 性能结果有配置、原始日志、统计与限制说明。
6. 作者原版保留完整，具备后续修改和比较条件。

不以复现原文绝对吞吐或最佳加速比为成功条件。不同 CPU、系统和线程条件下绝对性能可能不同。

## 3. 阶段路线与验收

### P0：准备与版本冻结

1. 检查 E 盘物理空间、宿主机与 WSL 可用内存、CPU flags、编译器。
2. 在项目内建立缓存、模型、环境、构建和结果目录。

4. 检查仓库说明和构建文件，保留许可证；创建开发分支。
5. 仅配置 CPU Release 构建，默认 `TABLE_ENTRY_SIZE=32`；不要打开 AVX512。
6. 先构建 `test-vlut-gemm`、`llama-bench`、`llama-batched` 所需目标，不构建不必要的服务功能。

产出：环境记录、Git SHA、CMake 配置、构建日志、可执行文件。

验收：以上目标构建成功，可查看帮助；未下载模型也可进入 P1。

### P1：理解 I2 核心路径并验证小矩阵

任务：

1. 按 CORE_DESIGN.md 追踪 I2_V_4 从权重打包到输出的调用链。
2. 用 g=4 的小例子手算一个 LUT 行及输出；解释共享索引与 N 维连续访问。
3. 增加轻量参考计算和类型筛选，不独立重写整个框架。
4. 验证三值权重打包/解码精确一致；验证整数 LUT 输出与相同量化激活的参考乘法一致。
5. 分别检查激活量化误差、布局/索引错误和累加溢出，不混为一个误差值。
6. 覆盖全零、全负或负峰值占优、正负极值、N 尾块及目标模型的受支持形状。

产出：正确性测试、结果日志、I2 调用链说明与静态风险核验结论。

验收：目标测试通过；异常有最小复现和明确处理决定。只有性能模式跑通不算验收通过。

产出：内核性能 CSV、统计图、参数说明。

验收：同配置重复测量基本稳定；能说明每个矩阵的 M/K/N 和结果分母。

## 4. 默认性能测试矩阵

| 类型 | 默认范围 | 主要指标 |
| --- | --- | --- |
| 内核 | 目标模型形状；线程 1/2/4 | µs/次、runs/s |
| Prefill | 输入长度 32/128/256/512；输出关闭或单独计时 | tokens/s、阶段耗时 |
| 尾块与短输入 | N=1/8/16/31/32/33/63/64/65 | 分块边界损失与正确性 |
| 并行 Decode | 先 1/4/8/16 个序列；固定输入和生成长度 | 合计生成 tokens/s、RSS |
| 资源 | 运行期间采集，区分模型加载与稳态 | 峰值 RSS、缺页/交换情况 |

测试先小后大；实际形状限制必须由代码检查和测试确认。不要为覆盖表格而强行运行不支持形状。单请求 Decode 测量用于描述边界，不承诺其是 Vec-LUT 优势场景。

建议每个 `results/<run-id>/` 保存：

- `manifest.json`：环境、SHA、模型 hash、线程、tile、shape、负载、构建参数。
- `commands.txt`：可复用命令；不保存令牌或其他凭据。
- `stdout.log`、`stderr.log`：原始记录。
- `metrics.csv`：每次测量数据，不只保存平均数。
- `summary.md`：结论、波动、异常和未测项目。

## 5. 初步优化候选：未确认收益

### A. 线程/执行上下文所属的可复用工作区（P2 后降为低优先级）

代码证据：I2_V_4 等内核每次调用 malloc/free 累加缓冲区与 LUT。

尝试：按线程或执行上下文持有工作区，容量不足再扩容，保留必要初始化。不使用会造成并发数据竞争的全局共享静态缓冲区。

先测：分配和清零的耗时占比、重复调用延迟、RSS 与并发正确性。

停止条件：成本占比很低，或复用并未产生稳定净收益。定位为工程优化，不能单凭此宣称独立研究创新。

### B. 短输入和尾块感知的向量 LUT 选择（保留为第二候选）

代码证据：TABLE_ENTRY_SIZE 为编译期参数；尾块存在按完整宽度建表/累加的路径。

尝试：维持同一权重布局，提供少数 token 宽度的专用内核；激活布局、建表和累加一起适配。先评估 16/32 宽度，再考虑更短路径，不一开始生成大量变体。

先测：N=31/32/33 等边界、短 Prefill、小批次 Decode；比较总成本而非仅查询循环。

边界：作者已有搜索脚本，论文也已讨论标量/向量切换。单纯搜索 tile 或重复该切换概念不算新颖。

停止条件：padding 不是主要损失、选择开销抵消收益、需维护两份大权重且资源代价过高，或最近邻已完整覆盖。

在 P5 有实测线索后，筛选约 12–20 篇，精读最接近的 5–8 篇。先关注 CPU LUT、短形状内核、数据布局、临时内存管理与轻量调度，不转向需要训练或 GPU 集群的课题。

优先阅读：

- [T-MAC](https://arxiv.org/html/2407.00088)：标量 LUT、线程池集成与布局。
- [bitnet.cpp](https://arxiv.org/html/2502.11880v1)：三值打包、累加和数值语义。
- [Pushing the Envelope of LLM Inference on AI-PC](https://arxiv.org/html/2508.06753v1)：CPU 微内核与小形状性能。
- [LUT-GEMM](https://arxiv.org/abs/2206.09557)：查表复用机制，辨别 GPU 思路是否可迁移。
- [TPP](https://arxiv.org/abs/2104.05755)：专用内核与调度抽象。
- [Ansor](https://arxiv.org/abs/2006.06762)：已有调优方法与新颖性边界。
- [PolyQ](https://arxiv.org/html/2607.14618v1)：较新的 CPU 布局处理思路，仅作为相关文献，不默认引入其量化方法。

每篇记录：实际阅读范围、问题、机制、已有功能、与本候选的重叠、可借鉴点、不能迁移的假设。每个候选给出最接近的反证，不以“没看到”证明“没人做”。

# P6 第二轮：分块提升转置的资源复核与选择性启用

2026-11-18。对照是同代码版本、保持正确性的 OFF 构建；作者原始 worktree 未改。仅测试本系统，没有引入其他框架。

## 当前属于什么工作

P0–P4 的目标路径复现已经完成；当前是 P6 的局部性能优化。作者提供了三值打包、Vector LUT、缓存分块与框架集成。本项目在复现中修正正确性问题，再优化修复版中较频繁的 INT16→INT32 提升转置；本轮进一步实现按实际形状和线程条件选择该遍历。

这属于有可测效果的工程改进候选。分块、循环交换、形状分派都是已有方法，不能声称发明 Vector LUT 或证明了研究新颖性。论文已有转换融合和参数选择；本轮与相关资料的具体关系见 [方法与资料](P6_REFINE_METHOD.md)。

## 改动位置与原因

`ggml/src/ggml-cpu/ggml-vlut-widen.h` 的 `vlut_i2v4_blocked_widen` 按16输出行处理一个局部块；`ggml-cpu-quants-vlut.c` 仅在 I2_V_4 的四个提升位置接入。

原来先遍历 token，再遍历全部行：从 `[M][32]` 的 INT16 源读取，内层步长64字节，写入 `[32][M]` 的 INT32 累加器。新实现每次处理16行的全部token，对应源数据块为1024字节，缩短源数据再次访问的间隔。目的在于改善局部性；没有 PMU/cache-miss 数据，不能宣称已直接测得某级缓存命中率增加。

每个输出元素仍恰好加一次相同的有符号数；保持安全K=128段、量化、权重、输出布局、独立清零和内存分配方式。不改变数值精度，不增加模型副本或生产内核大缓冲区。实验驱动同时驻留两个模型进程是测量方案，实际部署只需要一个。

本轮增加 `VLUT_I2V4_SELECTIVE_WIDEN`，默认OFF，与旧强制开关互斥。判定在每次内核入口计算一次：

```text
线程数 == 1 && tile宽度 == 32 && 线程输出行数 >= 2560
&& K >= 3072 && 有效token数 >= 32
```

满足后也只对完整32-token tile使用分块，尾tile沿用基线。没有模型名称判断。K约束来自大型M但K2048的退化观察；阈值是保守经验边界，不是理论最优点，也不保证未测试的所有更大矩阵都获益。Falcon的三类形状至少一维不满足，因此保守回退，可能放弃其中个别有益形状。

## 资源控制与波动原因

使用taskset与OpenMP places控制WSL虚拟CPU，记录逐样本亲和性、迁移、调度等待、进程CPU时间、缺页/交换和宿主CPU遥测。保持宿主平衡电源方案，没有改变全机电源或其他应用。

BitNet P128/单线程的强制分块复核共36样本：

|条件|OFF中位ms|ON中位ms|加速比|
|---|---:|---:|---:|
|旧OpenMP配置，实测也绑定CPU0|4588.34|4251.33|1.079|
|显式CPU0|4568.06|4206.26|1.086|
|显式CPU2|4500.90|4165.82|1.080|

所有这些样本均无迁移，进程CPU时间/墙钟约0.9992–0.9998，调度等待中位约1–3.6ms，相对4秒以上的前向很小；没有major faults或swap增量。因此本次不能把波动归因于客体线程迁移或明显抢占，也不能说“taskset修复了先前没有绑核的问题”。

上一轮OFF中位从5799ms降到4932ms，ON仅从4678ms降到4600ms，足以说明24%的首批比值含有明显的批间状态混杂。本轮两进程驻留、逐样本ABBA/BAAB交错使时间顺序更平衡，观测约8%的收益，但同时改变了实验组织，无法把差异单独归因于其中一个控制因素。

旧日志缺少足够的频率/调度证据；WSL不提供已确认的宿主P/E核映射。宿主遥测的频率比例不是对应物理核的实际Turbo频率，也不能证明独占核心。频率、宿主调度、缓存状态仍是可能因素，**具体物理根因尚不能唯一确定**。本次没有跨日、原生Linux或物理核独占复验。

## 形状筛查与选择规则依据

78配置、1560样本涵盖六种真实模型形状、N1/16/32/33/128/256和1/4线程，并加入M2560/3072/4096邻近点。150ms目标仅作筛查，所有样本及正负结果保留，完整表由 `analyze_p6_refine.py` 生成。

例如M8192/K2048/N256/单线程，强制分块两批约0.99/0.93x，即较大M也不保证获益。BitNet三种真实M/K在完整tile、单线程的多个正常长度均出现正向结果；多线程/尾部结果不够稳定。因此采用M、K、线程、完整tile共同约束，不仅凭矩阵大小全面启用。

## 正确性与路径验收

OFF、selected、selected-profile、selected-ASan四构建均通过：I2 164项及5非法输入/大工作区；I1 225项及K4/5非法输入；8个新增大图边界逐元素INT64参考；180项helper坐标/极值/保护边界检查和10项选择规则检查。ASan/UBSan没有报错。

新增图边界覆盖M2559/2560/2561、K3056/3072/3088、N31/32/33/65、2/4线程，检查选择阈值及未对齐的尾部。profile结构仍为128字节，新增计数复用padding，静态断言防止布局变化。计数只在诊断构建开启。

真实模型7个诊断配置全部通过：BitNet单线程P32/33/128有179/182目标调用选中；最后三个FFN矩阵因只需最后token而走N1基线。P32/P128的分块提升元素占约99.92%/99.98%，P33约96.89%；P16、Falcon P128、BitNet四线程以及单token Decode均不进入新helper。这里的比例是提升元素覆盖率，不能解释为总执行时间占比。

## 无插桩真实模型确认与决定

本轮选择性版本不能沿用强制ON复核的约8%作为其收益数字：它有额外选择逻辑，测量时段和构建也不同。应以本节同场OFF/selected对照为准。

P33只有约2%的改善，证据弱于P128/256；不据此单独宣称稳定的小幅收益。回退案例仍出现约1%–3%的差异，尤其BitNet四线程Decode约1.030x，但该路径的分块调用为零，不能归因于新helper；代码布局、分派条件和时变环境尚未分别隔离。没有给出“回退绝对零开销”的保证。

**决定：允许在本机已验证的BitNet I2_V_4、单线程、P32–256范围内显式试用选择性版本；仓库默认继续OFF。** 这覆盖正常Prefill长度，不是只对一个极端大矩阵成立。P33的收益较弱，完整块比例和额外尾tile工作会限制收益；尚不能从数据唯一分离各项代价。其他模型、CPU、长上下文和服务负载仍需验收。选择规则只控制提升遍历，不能把回退案例的细小正负差异称为优化收益或保证二进制完全无性能差别。

本轮进一步优化止于加入形状/线程/尾tile约束，没有同时融合清零或修改量化。此前清零仅占单线程阶段合计约1.9%–2.5%，完全消除也只有很有限的理想上限，因此暂不为此引入第二项变量。下一步优先跨独立会话复验同一选择规则，再在用户指定的另一CPU或额外正常模型形状验证；若要成为研究贡献，还须补最接近文献查重、机制证据与推广实验。

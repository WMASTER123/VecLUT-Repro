# P6.4：连续 INT32 累加、最终输出转换（预注册方案）

2026-11-18，在实施和测量之前确定。稳定基线 `79db4941`，独立分支 `exp/deferred-transpose-20261118`。旧自适应方案已在原实验分支删除，历史结果不计为本轮收益。

## 假设与最近邻

真实 Prefill 的 I2_V_4 每个 K 累加段都要提升并转置。P2 的提升转置占约31–37%，已有分块改善有限。假设：把 INT32 暂存改为 `[token_tile][output_row][valid_token]`，使每段提升时读写连续，只在最终 INT32→FP32 输出时转换布局，能降低整体矩阵/模型时间。

Vec-LUT v2 §3.3 已讨论 token 连续布局及输出转换融合，§3.4 已有 INT16/INT32 分级累加。本候选调整其代码中转换的发生时机，不宣称提出新的向量 LUT、首次融合或已确认研究创新。核对来源：https://arxiv.org/html/2512.06443v2 （本轮实际复读§3.3–3.4）。T-MAC 等已有布局/循环重排也属于相关机制，详见既有 LITERATURE_REVIEW.md；当前是工程动机实验。

## 最小实现与数值约束

- 两版都固定安全 K240，同一权重、激活、查表、清零、线程、tile32；对照启用既有选择性分块提升，候选采用连续提升。保留 legacy128 构建选项，但本轮不以弱基线计算候选收益。
- 单一默认 OFF 开关 `VLUT_I2V4_DEFERRED_TRANSPOSE`，只影响 I2_V_4；不改变 I1、量化、权重或浮点计算顺序。
- 完整tile连续提升；尾tile仅存有效token，INT32总空间仍为 `N*thread_rows*4` 字节。输入INT16行距T，尾tile输出行距valid，不读取无效lane。
- 最终 token r、行c的暂存索引：`(r/T)*T*rows + c*valid + r%T`，valid=min(T,N-(r/T)*T)。最终只做一次INT32→FP32及原scale乘法。
- K240×128=30720<32767，包含原始INT8 -128。最终 K≤INT32_MAX/128。布局变化不改变任何整数和。
- 不融合清零、不增加形状阈值、不扫参数、不改变内存分配生命周期。若失败直接删候选实现和选项。

## 验证顺序与停止条件

1. OFF/ON Release 和 ON ASan/UBSan：原P1、216累加边界、多tile/尾tile、多线程图、I1回归；任何错误先修正确性，不测错误版本性能。
2. 固定WSL CPU：1线程CPU2；4线程CPU0/2/4/6。无profile。六种真实模型矩阵形状 × N32/128 × 线程1/4 =24配置；两批反向顺序，每版每配置5样本，150ms目标，合计480样本。逐配置交换先后，禁止测试同时构建。
3. 图级门槛：超过12配置在两批都快5%以上，且任一批慢5%以上的配置≤2。未通过则删除候选，不做形状适配。记录CV和全部失败数据；筛查不是最终结论。
4. 过门后测两模型 Prefill P32/128、线程1/4及 P33尾部单线程；Decode P32/G8/线程1/4守护。每版6样本，ABBA/BAAB逐样本交错，逐case预热。CV>10%的case只允许原样追加一次10样本复核，不改代码/参数；仍噪声高则不作成功结论。
5. 模型门槛：8个主Prefill配置至少6个提升≥5%；所有主配置和尾部/Decode守护不得稳定退化>5%。不通过就删除候选，不选择成功子集启用。
6. 记录模型SHA256、二进制hash、源代码SHA/patch、输出logits哈希、非空Decode token、CPU绑定/调度、major fault/swap。I2所有输出按相同整数oracle校验；不能用空Prefill token数组当生成一致证明。
